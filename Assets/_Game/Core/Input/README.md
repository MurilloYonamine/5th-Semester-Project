# The `Input` Directory: Input Abstraction Layer

The **Input** layer abstracts Unity's new Input System, providing a clean interface for the rest of the game to request input without knowing about keyboard/gamepad/mouse details. This enables easy rebinding, input simulation for testing, and centralized input handling.

---

## Architecture Overview

The input system bridges two worlds:

1. **GameInput (Auto-generated)**: Unity's Input System wrapper with action maps and bindings
2. **IInputService**: Clean interface that gameplay systems use to request input
3. **Global Events**: Raw input translated into game events via EventBus

---

## Key Files

### `GameInput.inputactions`

Unity InputAction asset that defines all game inputs. This is a visual UI where designers can:
- Add new input actions (Jump, Move, Interact, etc.)
- Bind to keyboard keys, gamepad buttons, mouse
- Create action maps (Player, Menu, Editor)
- Define binding groups (Keyboard, Gamepad, Mouse)

**Structure:**

```
GameInput (Asset)
└── Player (Action Map)
    ├── Move         (Type: Value, Control Type: Vector2)
    ├── Look         (Type: Value, Control Type: Vector2)
    ├── Jump         (Type: Button)
    ├── Crouch       (Type: Button)
    ├── Sprint       (Type: Button)
    ├── Interact     (Type: Button)
    ├── Pause        (Type: Button)
    └── ... (other actions)
```

**Example Bindings:**

| Action | Keyboard | Gamepad | Mouse |
|--------|----------|---------|-------|
| Move | WASD | Left Stick | - |
| Look | - | Right Stick | Mouse Move |
| Jump | Space | A Button | Left Click |
| Sprint | Shift | LB Button | Right Click |
| Pause | Esc | Start Button | - |

### `GameInput.cs` (Auto-generated)

**⚠️ AUTO-GENERATED FILE** — Do not edit manually. Regenerated when `GameInput.inputactions` changes.

This file is generated by Unity's InputActionCodeGenerator and provides:

```csharp
public partial class GameInput : IInputActionCollection2, IDisposable
{
    // Action maps
    public @PlayerActions @Player { get; }

    // Individual actions
    public InputAction MoveAction { get; }
    public InputAction LookAction { get; }
    public InputAction JumpAction { get; }
    // ... etc

    // Enable/disable input
    public void Enable();
    public void Disable();
    public void Dispose();
}
```

**How it works:**

```csharp
// Create the generated input class
var gameInput = new GameInput();
gameInput.Enable();

// Get action value
Vector2 moveInput = gameInput.Player.Move.ReadValue<Vector2>();

// Get button state
if (gameInput.Player.Jump.WasPressedThisFrame())
{
    player.Jump();
}

// Rebind at runtime
gameInput.Player.Jump.Rebind()
    .WithPath("<Keyboard>/space")
    .WithPath("<Gamepad>/buttonSouth")
    .OnComplete(action => Debug.Log("Rebound Jump"))
    .Start();
```

### `IInputService.cs`

Clean interface that features use to request input without knowing implementation details.

```csharp
namespace FifthSemester.Core.Input
{
    public interface IInputService
    {
        GameState CurrentGameState { get; set; }
        
        void Enable();
        void Disable();

        void OnGameStateChanged(GameStateChangedEvent evt);
    }
}
```

#### Purpose

- Wraps raw Unity Input System input
- Manages input enable/disable based on game state
- Publishes input events to EventBus for decoupled systems
- Allows input to be mocked for testing

---

## Input Flow

```
Player presses Jump key
    ↓
GameInput detects action (auto-generated)
    ↓
InputService captures and publishes JumpInputEvent via EventBus
    ↓
Player system listens to JumpInputEvent and responds
    ↓
Player.Jump() is called

All without direct coupling!
```

## Usage Patterns

### 1. Subscribe to Input Events (Recommended)

```csharp
public class PlayerController : MonoBehaviour
{
    private IEventBus _eventBus;

    private void Start()
    {
        _eventBus = ServiceLocator.Get<IEventBus>();
        
        // Subscribe to input events
        _eventBus.Subscribe<MoveInputEvent>(OnMoveInput);
        _eventBus.Subscribe<JumpInputEvent>(OnJumpInput);
    }

    private void OnDestroy()
    {
        _eventBus.Unsubscribe<MoveInputEvent>(OnMoveInput);
        _eventBus.Unsubscribe<JumpInputEvent>(OnJumpInput);
    }

    private void OnMoveInput(MoveInputEvent evt)
    {
        _moveDirection = evt.Value;
    }

    private void OnJumpInput(JumpInputEvent evt)
    {
        Jump();
    }
}
```

### 2. Request Input Directly from IInputService

```csharp
public class PlayerController : MonoBehaviour
{
    private IInputService _inputService;

    private void Start()
    {
        _inputService = ServiceLocator.Get<IInputService>();
    }

    private void Update()
    {
        // Get current input state
        if (_inputService != null && _inputService.CurrentGameState == GameState.Gameplay)
        {
            HandleInput();
        }
    }

    private void HandleInput()
    {
        // ... use input data ...
    }
}
```

### 3. Input Conditional on Game State

The `InputService` automatically enables/disables input based on `GameState`:

```csharp
// When game transitions to Paused state
eventBus.Publish<GameStateChangedEvent>(new(GameState.Gameplay, GameState.Paused));

// InputService receives this event and:
// - Disables input capture (player can't move)
// - Pause menu input is enabled

// When returning to Gameplay
eventBus.Publish<GameStateChangedEvent>(new(GameState.Paused, GameState.Gameplay));

// InputService re-enables player input
```

## Adding New Input Actions

### Step 1: Open GameInput.inputactions

In the Inspector or Assets, double-click `GameInput.inputactions` to open the Input System UI.

### Step 2: Add Action to Player Action Map

1. Select **Player** action map
2. Click **+ Action** button
3. Name it (e.g., "Reload")
4. Set Type: **Button** (or **Value** for analog sticks)

### Step 3: Add Bindings

1. Select the new action
2. Click **+ Binding**
3. Choose control path:
   - Keyboard: `<Keyboard>/r`
   - Gamepad: `<Gamepad>/buttonNorth`
   - Mouse: `<Mouse>/leftButton`

### Step 4: Define Event in GlobalEvents.cs

```csharp
public readonly struct ReloadInputEvent { }
```

### Step 5: Publish Event from InputService

Update `InputService` to listen for the new action and publish the event:

```csharp
private void Update()
{
    if (_gameInput.Player.Reload.WasPressedThisFrame())
    {
        _eventBus.Publish<ReloadInputEvent>(new());
    }
}
```

### Step 6: Subscribe to Event in Your Feature

```csharp
public class Weapon : MonoBehaviour
{
    private void Start()
    {
        IEventBus eventBus = ServiceLocator.Get<IEventBus>();
        eventBus.Subscribe<ReloadInputEvent>(OnReloadInput);
    }

    private void OnReloadInput(ReloadInputEvent evt)
    {
        Reload();
    }
}
```

## Runtime Input Rebinding

Allow players to customize controls:

```csharp
public class InputRebindUI : MonoBehaviour
{
    private GameInput _gameInput;

    public void RebindJump()
    {
        var jumpAction = _gameInput.Player.Jump;

        jumpAction.PerformInteractiveRebinding()
            .OnComplete(operation =>
            {
                Debug.Log($"Jump rebound to: {jumpAction.effectivePath}");
                operation.Dispose();
            })
            .Start();
    }
}
```

## Best Practices

### 1. Always Use InputService via ServiceLocator

❌ **Bad:**
```csharp
public class Player : MonoBehaviour
{
    private GameInput _input = new GameInput();

    private void Start()
    {
        _input.Enable();
    }
}
```

✅ **Good:**
```csharp
public class Player : MonoBehaviour
{
    private IEventBus _eventBus = ServiceLocator.Get<IEventBus>();

    private void Start()
    {
        _eventBus.Subscribe<MoveInputEvent>(OnMove);
    }
}
```

### 2. Subscribe to Events, Don't Poll Input

❌ **Bad:**
```csharp
private void Update()
{
    if (Input.GetKeyDown(KeyCode.Space))
    {
        Jump();
    }
}
```

✅ **Good:**
```csharp
private void Start()
{
    _eventBus.Subscribe<JumpInputEvent>(OnJump);
}

private void OnJump(JumpInputEvent evt)
{
    Jump();
}
```

### 3. Let InputService Manage Enable/Disable

❌ **Bad:**
```csharp
// Don't manually disable input in pause menu
_input.Disable();
```

✅ **Good:**
```csharp
// InputService automatically disables input when not in Gameplay state
// Just listen to game state changes
_eventBus.Subscribe<GameStateChangedEvent>(OnGameStateChanged);
```

### 4. Use Readable Action Names

❌ **Bad:**
```csharp
// In GameInput.inputactions
Action1, Action2, Action3  // What do these do?
```

✅ **Good:**
```csharp
// In GameInput.inputactions
Move, Look, Jump, Crouch, Sprint, Interact, Pause
```

### 5. Group Bindings by Intent

✅ **Good:**
```csharp
// All "movement" actions in one conceptual group
Player/Move
Player/Sprint
Player/Crouch

// All "interaction" actions together
Player/Interact
Player/Reload
```

## Input System State Machine

```
Start()
    ↓
GameInput created and enabled
    ↓
Listen for GameStateChangedEvent
    ↓
┌─ GameState == Gameplay?
│       ├─ YES: InputService publishes MoveInputEvent, JumpInputEvent, etc.
│       └─ NO: InputService stops publishing (disable input)
└─ Features receive events and respond
```

## Debugging Input

### Enable Input Debug UI

```csharp
// In InputService or a debug manager
InputActionDebugExtensions.SetDebugUIEnabled(true);
// Shows on-screen which inputs are active
```

### Log Input Events

```csharp
public class InputDebug : MonoBehaviour
{
    private IEventBus _eventBus;

    private void Start()
    {
        _eventBus = ServiceLocator.Get<IEventBus>();
        
        _eventBus.Subscribe<MoveInputEvent>(evt => 
            Debug.Log($"Move: {evt.Value}"));
        _eventBus.Subscribe<JumpInputEvent>(evt => 
            Debug.Log("Jump pressed"));
```

## Summary

The **Input** subsystem provides:
- **Abstraction** over Unity's Input System
- **Centralized input management** via `IInputService`
- **Event-driven input** published to EventBus
- **State-aware input** (disabled in menus, enabled in gameplay)
- **Easy rebinding** at runtime
- **Testable input** (mock `IInputService` for unit tests)

By using `IInputService` and EventBus, PHOTOSSYNC achieves **clean separation** between input handling and gameplay logic.
